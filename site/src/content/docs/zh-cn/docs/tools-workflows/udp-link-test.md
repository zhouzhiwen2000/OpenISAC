`UdpLinkTest` 发送带序号、内容已知的 UDP 数据包，由 BS 经空口传给 UE，
UE 上的接收程序逐包检查恢复的数据。统计界面运行在 **BS 电脑**，同时显示两端状态。

## 两台电脑均编译测试程序

在 OpenISAC 目录执行：

```bash
cmake -S . -B build
cmake --build build --target UdpLinkTest -j4
```

统计界面使用项目的 Python 环境，需要安装 PyQt6、pyqtgraph、NumPy 和 pyzmq。

## 启动测试

先使用匹配的射频配置启动 BS 和 UE 后端。开始测试前，停止视频推流、播放器和占用
UE 输出端口的转发程序。以下示例使用 BS 输入 `127.0.0.1:50000`、UE 输出
`127.0.0.1:50001`，请与后端 YAML 中的配置保持一致。

**在 UE 电脑**先启动接收程序。将 `192.168.50.1` 替换为 BS 电脑在管理网络上的地址：

```bash
./build/UdpLinkTest rx --port 50001 \
  --telemetry tcp://0.0.0.0:18101 \
  --sender-telemetry tcp://192.168.50.1:18100
```

**在 BS 电脑**启动 50 Mbps 数据流：

```bash
./build/UdpLinkTest tx --port 50000 --rate-mbps 50 --packet-bytes 1316 \
  --telemetry tcp://0.0.0.0:18100
```

**在 BS 的另一个终端**启动统计界面。将 `192.168.50.19` 替换为 UE 的管理地址：

```bash
python scripts/plot_udp_link.py \
  --tx tcp://127.0.0.1:18100 --rx tcp://192.168.50.19:18101 \
  --control tcp://127.0.0.1:18102 --code-rate 1/2 --rate-mbps 50
```

修改“目标速率”并点击“应用”，可在线调整发送速率；设为零可暂停发送。
在“LDPC 码率”中输入 `1/2`、`2/3` 等分数并按回车，可更新编码后速率显示。
将此值设为与两端 YAML 的 `ldpc.code_rate` 一致；此输入项只更新速率显示。实际编码码率需在 YAML 或配置编辑器中修改，再重启两端后端。

停止时先按 Ctrl+C 结束发送程序，至少等待一秒，让接收端确认末尾的数据包统计，
再结束接收程序。关闭统计窗口不会停止收发程序。需要开始一轮新测试时，重新启动
两端测试程序。

## 统计口径

- **发送速率**：每秒成功提交到 BS UDP 输入端口的数据量，包括测试包的包头和内容，
  不含 IP、UDP 和以太网协议头。
- **接收速率**：每秒实际收到的数据量，包含有误比特的数据包。可识别的重复包、其他
  测试轮次的数据包以及超出保留序号窗口的旧包不计入。测试包头无法恢复的数据包仍计入
  接收速率。
- **LDPC 编码后速率**：显示的 UDP 数据率除以用户输入的 LDPC 码率，不包含空口额外的
  帧结构、填充、导频及 CP 开销。
- **丢包率**：缺失的可识别序号数量除以已确认发送包数。默认保留一秒等待时间，容纳
  传输延迟与乱序；发送端统计还能补齐首包之前、末尾及完全断流期间的丢包。保留窗口内
  的迟到包会修正累计丢包数。
- **误比特率 BER**：已收到、序号可识别且未重复的数据包中，不一致比特数除以已比较
  比特数。可恢复包头内的误比特也计入；丢包不计作误比特。包头完全无法恢复时，无法
  比对该包，其序号仍计为缺失。

JSON 统计同时提供重复包、乱序包、迟到包、无效包头和发送错误计数。若发送端统计
连接中断，只能根据最高已收到序号推断缺包，无法确定末尾及完全断流期间的丢包；测试时
应保持管理网络连通。

默认包长为 1316 字节。运行 `--help` 可查看包长、有限包数、持续时间和统计接口选项。
测试数据通过 UDP 传输，统计信息和码率控制通过管理网络上的 ZeroMQ 传输。
