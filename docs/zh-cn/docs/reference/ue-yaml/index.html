UE YAML 参考

使用说明

Section titled “使用说明”

UE 从启动时的当前工作目录读取 UE.yaml。建议先复制与硬件和场景匹配的 config/UE_*.yaml 模板，再在副本上修改。配置不会在运行中自动重载；修改后需要重启 UE。

下表按 YAML 顶层结构排列，并使用 uplink.arq_enabled 这样的完整路径区分同名字段。“典型值”用于说明常见配置，不代表所有模板的默认值。可选配置节省略时，程序使用解析器默认值。

帧结构、上下行双工、频率和资源映射等联动参数必须与 BS 配置一致。

modulation

Section titled “modulation”
路径类型默认值说明
modulation.schemestringQPSK业务载荷调制方式：BPSK、QPSK、8PSK、16QAM、32QAM 或 64QAM。同时用于上下行，BS 与 UE 必须一致，重启后生效。

在两端 YAML 中添加或修改：

也可在 config_web_editor 的 BS、UE 页面中选择 Payload modulation / scheme 并保存。两端停止后修改配置，再使用原启动脚本重新启动。省略该配置时使用 QPSK。

所有载荷星座均采用 Gray 编码，并归一化到单位平均符号能量。32QAM 为 8×4 矩形星座。同步序列和导频保持原设计，包标记、包头及帧标识仍使用 QPSK。调制方式由两端配置约定，不进行自动协商。

每个载荷符号分别承载 1、2、3、4、5、6 个编码比特。较高阶调制需要更好的信噪比、相位稳定性和射频线性度；在相同采样率和资源网格下可提高理论载荷容量，实际 UDP 吞吐还取决于 LDPC 处理能力、帧开销和丢包情况。详见软解调与 LDPC。

usrp_device

Section titled “usrp_device”
参数类型/单位典型值说明
usrp_device.device_argsstringaddr=...USRP 设备参数，例如网络地址。
usrp_device.clock_sourcestringexternalUE 时钟源：internal、external 或 gpsdo。
usrp_device.time_sourcestringinternalUE 时间/PPS 源。空值按 internal 处理；pps_phase 要求它与 clock_source 都显式为 external。

只要 usrp_device.clock_source 非空，CPU、CUDA 和 HIP UE 都会在任何 stream 开始前执行严格的 device-time 对齐，该步骤与所选 sync_tracking.ocxo_mode 无关。 这也包括 time_source: internal；time_source 只选择 PPS 输入，不再决定是否 执行启动对齐。启动过程先观察一次 PPS 跳变，再武装 set_time_next_pps(0)，并等待 device time 计数器确实回跳且 time_last_pps=0；PPS 缺失、backend 不支持或验证 失败都会中止启动。对 gpsdo，对齐会有意 用零点替换原有的类 UTC device-time epoch。该步骤对齐软件时间原点，但 X310 在 200 MHz master clock 下仍保留 5 ns 的 PPS 捕获量化。

ldpc

Section titled “ldpc”
参数类型/单位典型值说明
ldpc.decoder_iterationsint12CPU LDPC 最大迭代次数，必须大于等于 1；保留 syndrome 提前结束。
ldpc.nms_normalization_factorfloat0.75CPU NMS 归一化系数，有限值且在 (0, 1] 内；Q16 模式使用 0.125 的整数倍。
ldpc.fixed_pointboolfalse使用 int16/Q16 CPU LDPC 解码路径。
ldpc.fixed_point_scaleint16int16 饱和前的 LLR 缩放。

这两项用于 UE 下行的 CPU 译码，float32 和 Q16 共用设置。省略时使用 12 次迭代和系数 0.75。已有 YAML 的显式值继续生效；要在已有配置中使用这组默认值，请更新这两项。可在 Web 配置控制台 的 LDPC decode 中修改，保存后重启后端。Q16 支持 0.125、0.25、0.375、0.5、0.625、0.75、0.875、1.0；LLR 比例仅在 fixed_point: true 时参与计算。增加迭代次数可能改善纠错，同时增加弱信号时的计算量。

sync_tracking.ocxo_pps_initial_ap_enablebooltrue保留的旧键名。在 pps_phase 中，每次 FllSlow -> Phase 都启动一次 PPSOUT 对齐事务，再放行 SF Phase 跟踪。关闭时启动日志会告警：大 residual 只能由限斜率 PI 处理，可能收敛很慢。

sync_tracking.ocxo_pps_initial_ap_command_timeout_sfloat / s3.0AP worker 的总墙钟预算，包含全部 JAMSYNCING 重试；aligner 额外等待 0.5 s 终态余量，worker 截止后不再发送该 AP。
sync_tracking.ocxo_pps_initial_ap_max_retriesint1AP 已接受但在 settle_s + command_timeout_s 内没有新 publication 时的有界重试次数（0..3）；重试会等待新的有效观测并按残差重算 AP。

sync_tracking.cfo_ewma_alphafloat0.02EWMA 对新样本权重（0..1；越大跟踪越快、噪声越大）。

硬件预设使用 ocxo_fll_slow_kp=0.1、ocxo_fll_slow_ki=0.007、 ocxo_fll_slow_max_slew_ppm_per_s=0.005 和 ocxo_fll_slow_enter_abs_ppm=0.0005，并保留 ocxo_fll_slow_deadzone_ppm=5.0e-5、ocxo_phase_kp=2.0e-4、 ocxo_phase_ki=1.0e-6 与 ocxo_phase_enter_sfo_abs_ppm=2.0e-4。 每次进入 Phase 的 PPSOUT AP 校正默认开启，并使用台架实测确认的正命令极性。

普通重新同步只重置 OCXO 观测、dwell 计时和控制阶段，不再向 DAC 写入零码字。 控制器从执行器保留的 command 重新起步；执行器在重新入锁后的第一条实际非零修正时 才重置 slew 时间基准，因此 search 时长不会放大第一步。每条 SF 收到 OK 后， 非实时串口 worker 会持久化更新 ocxo_dac_state_file；下次启动 UE/CUDAUE 进程时，DAC 与控制器都从该已确认的 raw word 恢复，而不是从零开始。正常退出时先结束串口 worker，再次保存最后一条实际收到 OK 的 SF word；更新但未确认的 queued word 不会被提升为下次启动的稳态值。 恢复时还要求文件中的串口设备、zero_word 和 ppm_per_lsb 与当前配置一致。文件缺失时 从校准零码字启动，并在命令确认后创建状态；文件损坏、设备或标定不匹配、word 越界时也 回退到零码字，但原文件保持不变，且本次进程关闭持久化，需修复或删除该文件后再重启。 该机制假定仅重启 UE 进程时外部 DAC 仍保持供电并保留原码字。

auto 和 phase 保留原来的 Phase anchor：PI 控制 setpoint - TO_clock，继续支持 freeze_on_lock、zero、fixed；这两个 模式不会读取 time_last_pps()，也不会进入 AP gate。

pps_phase 是单独的显式模式。对下行帧 N，eRTM 根据每份 ERTM5 报告 打包前实时刷新的 BS frame-0/PPS 锚点重建 r_B=B_N-P_B，根据 UE 帧边界 与 PPS 时间戳得到 r_U=U_N-P_U。Phase 误差为 wrap_1s(tau_DL_RF - TO_UE + r_B - r_U) = wrap_1s(P_U-P_B)，目标为零。 该模式要求 sync_tracking.hardware_sync=true、uplink.ertm_to_enable=true， 并要求 usrp_device.clock_source 与 usrp_device.time_source 都显式配置为 external；空 time_source 按 internal 处理。任一条件不满足都会报配置错误。 BS 侧生成 PPS anchor 时也必须使用连接 PPSDO 的 external clock/time source。 BS anchor 的刷新频率由 uplink.ertm_report_interval_frames 的 eRTM 报告周期决定， 并在 TX/调制实时路径之外执行。每次 FllSlow -> Phase 时，AP gate 都会重新武装， 并根据最新有效 PPS residual 计算一次校正；在同一次 Phase 停留期间保持 Done， 普通 Phase 更新和 Freeze 不会重复 AP。若 Phase 退回 FLL 后再次进入，则允许一次 新的校正。AP 仅改变 PPSDO 的 PPSOUT，不会重设 USRP 时间、重锚 air-frame clock、清空 eRTM 状态或重新建立 TO。若旧 AP 仍处于 Queued/InFlight，新一次进入会 等待硬件回到 Idle，而不是把 Busy 当作终端失败；JAMSYNCING 重试仍属于同一次 AP 请求。

LoS 相位参考

Section titled “LoS 相位参考”

该选项可在收发机使用独立时钟或时钟稳定性较差、同步后仍存在残余公共相位漂移时，改善双站感知的慢时间相干性和多普勒稳定性。启用前必须保证收发机之间有稳定的视距（LoS）直达路径，而且收发机两者相对静止。 被感知目标仍可运动。仅有非视距路径，或收发机之间存在相对运动时，不应启用：参考路径自身的运动也会被从测得的多普勒中减去。

在 UE Linux 主机的实际运行配置 UE.yaml 中合并以下字段：

这是启动时读取的 YAML 配置开关，也可以在 Web 配置页编辑。保存后需重启 UE 才会生效，目前没有对应的在线启停命令。

相位校正在现有 CFO/SFO/时延及系统响应校正之后、MTI 之前，消除双站 CSI 的残余公共相位，适用于完整信道矩阵输出（dense）。

每个慢时间采样行用 Hamming 加权的直达径分量作为参考，对所有子载波施加模长为 1 的共轭旋转，保留幅度。参考跟随已知的 ALGN 显示平移：只在测量参考时抵消对应相位斜坡，输出仍保留用户指定的时延平移。平移变化会清空未完成的感知批次和 MTI/微多普勒历史，避免混合两个显示坐标。直达径需要静止且占主导：显示的多普勒相对于该参考路径；若参考路径运动，其运动也会被减去。此功能不校正射频采样时钟。

sensing.phase_reference_min_coherence 默认 0.05，范围为 (0, 1]。相干度定义为 |sum(w H)|² / (sum(w) sum(w |H|²))，其中 w 为 Hamming 权重，H 为抵消已知显示相位斜坡后的信道值。参考过弱、接近零或出现非有限值时，整批感知数据被丢弃并清空 MTI/微多普勒历史，通信样本不受影响。缺少慢时间采样点时会重建感知窗口和历史，以保持多普勒处理所需的均匀时间轴。

修改这些 YAML 字段后重启 UE，在 UE Linux 主机启动日志中确认 static LoS phase reference enabled before MTI。若频繁出现 weak/invalid LoS phase reference，说明该路径不适合作为参考，应关闭此功能或改善直达径信号。

感知帧抽取

Section titled “感知帧抽取”

当较低 STRD 导致感知处理或上位机负载过高时，可设置 sensing.frame_decimation: 5，每 5 个完整感知帧（CPI）输出 1 帧。默认 1 输出全部帧。上位机的 Frame every N 输入框和 Set 按钮可在线调整，Params 中的 every=N 显示后端回报值；在线修改不写回 YAML，启动默认值可通过 config_web_editor 保存。

抽取保留每个输出帧内的符号间隔、采样点数和多普勒无模糊范围，降低画面刷新率。采样、信道估计和 MTI 保持连续；跳过帧的距离–多普勒 FFT、检测及数据发送不再执行，因此主要降低后级处理和传输负载。多通道使用相同的帧选择规则。

帧间空档会中断微多普勒历史累积，较大的抽取倍数可能无法积累足够长的连续窗口；需要连续微多普勒分析时使用 1。这项设置不改变通信数据传输或射频发射时序。更新后应配套使用同一版本的后端和上位机。
