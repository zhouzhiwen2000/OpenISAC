Docker deployment

The OpenISAC Docker image contains UHD, Aff3ct, BS, UE, ChannelSimulator and UdpLinkTest, so nothing needs to be installed or compiled on the host. The container still uses the host’s network interfaces, CPU cores and USB devices directly. It uses the same radio configuration as a native installation; timing also depends on host scheduling and tuning.

Requirements

Section titled “Requirements”
  • Native Linux with Docker Engine; Ubuntu 24.04 is recommended. Use the standard Docker Engine installation, not rootless Docker. Docker Desktop and WSL are suitable for simulation only.
  • An x86-64 CPU with AVX2 support (Intel Haswell, AMD Zen or newer).

Run all commands below from the root of the OpenISAC repository. If your account is not in the docker group, prefix them with sudo; files created by the container still belong to your own user.

3. Start BS and UE

Section titled “3. Start BS and UE”

What to expect:

  • Configuration changes take effect on the next start. Edit the file in my-config/ and restart the program. The container never modifies your file.
  • Logs and runtime files are written to docker-run/BS/ and docker-run/UE/ in the current directory. Use --work-dir DIR to choose another location, and give every program running at the same time its own work directory.
  • Networking works as if the program ran directly on the host; no port mapping is needed. When several instances run at the same time, give each one different control and viewer ports in YAML.
  • CPU core numbers in YAML are the host’s CPU numbers, as in a native installation.

Without --config, a built-in preset is used: add x310 (default), b210, sim or sim-duplex after the program name, for example scripts/docker_run.sh BS b210. The preset is copied into the work directory on the first run, and later runs reuse that copy. To switch to another preset, delete BS.yaml/UE.yaml from the work directory or use a new work directory.

USRP firmware compatibility

Section titled “USRP firmware compatibility”

The image uses UHD 4.11. Before the BS or UE starts, the USRPs in its configuration are checked for compatibility with this version. To check a USRP without starting OpenISAC:

If an X300/X310 has an incompatible FPGA image, it is updated automatically to the matching official image before OpenISAC starts:

  • The current image is backed up first, to ~/.local/state/openisac/firmware/<serial>/ (choose another location with --firmware-state DIR). Keep the backup in case you need to restore the old image.
  • Do not power off or disconnect the USRP during the update, which takes a few minutes. Some devices need a power cycle afterwards; you are told when this is the case.
  • After the update, the USRP may no longer work with older UHD versions installed elsewhere.
  • Compatible devices are never modified, and nothing is written when the device cannot be identified reliably. If one device string contains several X310s (addr0=...,addr1=...), run usrp-check on each address first.
  • If an update fails, automatic updates for that USRP are paused. Power-cycle the device and start again. If it is still incompatible, transaction.json in the device’s backup folder contains a command that restores the saved image. Once the device works again, move that file away to re-enable automatic updates.

To turn automatic updates off, for example when you use a custom FPGA image, start with OPENISAC_AUTO_UPDATE_FIRMWARE=0; an incompatible device then stops startup with an error instead. B200/B210 never need an update: UHD loads their firmware every time the device is opened.

Launcher options

Section titled “Launcher options”

scripts/docker_run.sh [options] PROGRAM [arguments]

OptionPurpose
--config FILEYAML configuration, re-read on every start
--work-dir DIRFolder for logs and runtime files (default docker-run/PROGRAM)
--name NAMEContainer name, for use with docker stop
--usbAllow access to USB USRPs (B200/B210)
--isolation-plan FILEUse the CPUs saved by isolate_cpus.py
--cpuset-cpus LISTLimit the CPUs the container may use
--memory SIZELimit container memory, for example 4g (unlimited by default)
--firmware-state DIRFolder for USRP firmware backups
--uhd-images DIRUse UHD firmware/FPGA images from a host folder
--image IMAGEUse another image instead of openisac:cpu
--dry-runPrint the Docker command without running it
Environment variablePurpose
OPENISAC_REQUIRE_RT=0Allow starting without real-time scheduling
OPENISAC_AUTO_UPDATE_FIRMWARE=0Disable automatic X300/X310 FPGA updates

Stopping

Section titled “Stopping”

Press Ctrl+C, or run docker stop NAME for a container started with --name. If a firmware update is in progress, the container finishes it before exiting.

Troubleshooting

Section titled “Troubleshooting”
SymptomSolution
Real-time prerequisites unavailableUse standard (rootful) Docker Engine on native Linux, or start with OPENISAC_REQUIRE_RT=0 for development runs
Configured CPU IDs are outside the container CPU setThe YAML uses CPU cores excluded by --cpuset-cpus or the isolation plan; adjust one of them
USRP not foundCheck the USRP address in YAML and the host network settings; for B210, add --usb
Frequent overflows (O) or underflows (U)Apply the socket-buffer setting above and follow System Performance Tuning
Simulation does not startStart ChannelSimulator first, and use the same simulation.session in all configurations
