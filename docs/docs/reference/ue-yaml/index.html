UE YAML Reference

How to use this page

Section titled “How to use this page”

UE reads UE.yaml from its current working directory at startup. Copy a config/UE_*.yaml preset that matches your hardware and scenario, then edit the copy. Configuration is not hot-reloaded; restart the UE after making changes.

The tables follow the top-level YAML structure and use full paths such as uplink.arq_enabled to distinguish similarly named fields. A typical value is guidance, not a guaranteed default for every preset. If an optional section is omitted, the parser supplies its default values.

Keep coupled frame-structure, duplex, frequency, and resource-mapping fields consistent with the BS configuration.

Add or edit the following in both YAML files:

Alternatively, select Payload modulation / scheme on both the BS and UE pages in config_web_editor and save. Stop both backends before changing the files, then restart using your usual launch script. Omitting this section selects QPSK.

All payload constellations use Gray labels and unit average symbol energy. 32QAM uses an 8×4 rectangular constellation. Synchronization sequences and pilots retain their existing design; packet markers, headers, and frame identities remain QPSK. The six modes carry 1, 2, 3, 4, 5, and 6 coded bits per payload symbol respectively. Higher orders require better SNR, phase stability, and RF linearity. They increase theoretical payload capacity at a fixed sample rate and resource grid; actual UDP throughput also depends on LDPC processing capacity, frame overhead, and packet loss. Section titled “usrp_device”
PathType/UnitTypical ValueDescription
usrp_device.device_argsstringaddr=...USRP device args.
usrp_device.clock_sourcestringexternalUE clock source: internal, external, or gpsdo.
usrp_device.time_sourcestringinternalUE time/PPS source. Empty resolves to internal; pps_phase requires this and clock_source to both be external.

Whenever usrp_device.clock_source is non-empty, CPU, CUDA, and HIP UE perform strict device-time alignment before any stream starts, independently of the selected sync_tracking.ocxo_mode. The hardware presets use ocxo_fll_slow_kp=0.1, ocxo_fll_slow_ki=0.007, ocxo_fll_slow_max_slew_ppm_per_s=0.005, and ocxo_fll_slow_enter_abs_ppm=0.0005. They retain ocxo_fll_slow_deadzone_ppm=5.0e-5, ocxo_phase_kp=2.0e-4, ocxo_phase_ki=1.0e-6, and ocxo_phase_enter_sfo_abs_ppm=2.0e-4. The PPSOUT AP correction is enabled on every Phase entry and uses the bench-confirmed positive command polarity by default.

Normal synchronization reacquisition resets OCXO observations, dwell timers, and loop stages without writing the DAC zero word. The discipliner restarts at the actuator’s retained command. The actuator rebases its slew timer at the first actual nonzero post-lock correction, so time spent searching cannot inflate that correction. After an SF command receives OK, the non-real-time serial worker durably updates ocxo_dac_state_file. On the next UE/CUDAUE process start, that acknowledged raw word initializes both the DAC and controller instead of starting at zero. During graceful shutdown, the serial worker is stopped first and the last SF word that actually received OK is saved again; a newer unacknowledged queued word is never promoted to the steady-state restart value. Restore also requires the saved serial device, zero_word, and ppm_per_lsb to match the active configuration. A missing file starts from the calibrated zero word and is created after an acknowledged command. A corrupt, mismatched, or out-of-range file also falls back to zero, but remains unchanged and disables persistence for that process run; fix or remove it before restarting. This assumes the external DAC itself remains powered and retains its word while the UE process restarts.

auto and phase preserve the existing Phase anchor: the PI controls setpoint - TO_clock, including freeze_on_lock, zero, and fixed. They do not read time_last_pps() or run the AP gate.

pps_phase is a separate explicit mode. For downlink frame N, eRTM reconstructs r_B=B_N-P_B from the BS anchor refreshed immediately before each ERTM5 report is packed, and obtains r_U=U_N-P_U from the UE frame-boundary and PPS timestamps. Its Phase error is wrap_1s(tau_DL_RF - TO_UE + r_B - r_U) = wrap_1s(P_U-P_B), with target zero. This mode is rejected unless sync_tracking.hardware_sync=true, uplink.ertm_to_enable=true, and both usrp_device.clock_source and usrp_device.time_source are explicitly external; an empty time_source means internal. The BS must likewise use the PPSDO-connected external clock and time sources when producing the PPS anchor. The BS anchor refresh runs at the eRTM report cadence configured by uplink.ertm_report_interval_frames, outside the TX/modulation real-time path. On every FllSlow -> Phase transition, the AP gate is rearmed and computes one correction from the latest valid PPS residual. It remains done throughout that Phase residence, so normal Phase updates and Freeze do not repeat AP. If Phase falls back through FLL and later re-enters, one new correction is allowed. AP changes PPSDO PPSOUT only and never resets USRP time, reanchors the air-frame clock, clears eRTM state, or rebuilds TO. If the previous AP is still queued or in flight, the new entry waits for hardware Idle instead of treating it as a terminal queue failure. JAMSYNCING retries reuse the same AP request.

LoS phase reference

Section titled “LoS phase reference”

This option can improve bistatic sensing coherence and Doppler stability when independent or less stable transmitter/receiver clocks leave residual common phase drift after synchronization. It requires a stable line-of-sight (LoS) path between the transmitter and receiver, and the two radios must remain stationary relative to each other. Sensing targets may still move. Do not enable it for NLoS-only links or when the transmitter and receiver move relative to each other: motion of the reference path would also be subtracted from the measured Doppler.

On the UE Linux host, merge these fields into the active UE.yaml:

This is a startup YAML option, also editable in the Web Config Console. Save the YAML and restart the UE to apply it; there is currently no online enable/disable command for this option.

The correction removes residual common phase from bistatic CSI in dense output mode after CFO/SFO/delay and system-response correction, before MTI.

Each slow-time row uses a Hamming-weighted LoS reference and a unit-magnitude conjugate rotation on all subcarriers. The reference follows the known ALGN display translation: it cancels that phase ramp only while measuring the reference, and retains the requested delay shift in the output. A translation clears the incomplete sensing batch and MTI/micro-Doppler history so the two display coordinates are not mixed. Amplitudes are preserved. The direct path must be static and dominant: the displayed Doppler is relative to this path; a moving reference also subtracts its own motion. This does not correct the radio sample clock.

sensing.phase_reference_min_coherence defaults to 0.05, with range (0, 1]. Coherence is |sum(w H)|² / (sum(w) sum(w |H|²)), where w is the Hamming weight and H is evaluated after cancelling the known display phase ramp. A weak, near-zero or non-finite reference rejects the entire sensing batch and clears MTI/micro-Doppler history. Communication samples are unaffected. Missing slow-time samples reset the sensing window and history to keep Doppler processing on a uniform timeline.

Restart the UE after changing these YAML fields. On the UE Linux host, check the startup log for static LoS phase reference enabled before MTI. Frequent weak/invalid LoS phase reference messages indicate that this path is unsuitable as a reference; disable the feature or improve the direct-path signal.

The packet is a fixed 152-byte little-endian frame: magic, version, channel count, sequence, Unix-nanosecond source timestamp, the original 16 float32 values, and a typed PPS diagnostic trailer. The trailer and CSV append r_bs_samples and r_ue_samples (float64), bs_last_pps_ticks, bs_t0_to_pps_ticks, and ue_last_pps_ns (exact int64), plus bs_tick_rate and sample_rate (float64). These fields distinguish BS-anchor, UE-PPS-latch, and TO discontinuities without passing absolute timestamps through float32. The viewer still accepts legacy OCXODBG2 packets. Launch the rolling viewer with python3 scripts/plot_ocxo_debug.py. Use --channels 6,7,8,13,15 to choose initial curves and --record capture/ocxo.csv to start CSV recording; automatic names use ocxo_debug_YYYYMMDD_01.csv and increment to _02, _03, and so on for later captures on the same day. Recording always stores all channels even when only a subset is visible. Periodic state packets are supplemented by immediate control, stage-transition, TO-jump, and Alignment event packets so one-frame delta channels are not lost.

Sensing frame decimation

Section titled “Sensing frame decimation”

If a low STRD overloads sensing processing or the viewer, set sensing.frame_decimation: 5 to output one complete sensing frame (CPI) out of every five. The default, 1, keeps all frames. Adjust it live with the viewer’s Frame every N input and Set button; every=N in Params shows the value reported by the backend. Live changes do not write YAML; save the startup setting with config_web_editor.

Decimation preserves each retained frame’s symbol spacing, sample count, and unambiguous Doppler interval while reducing the display update rate. Sampling, channel estimation, and MTI continue; omitted frames skip range–Doppler FFTs, detection, and transmission, primarily reducing downstream processing and transport load. All sensing channels use the same frame-selection rule.

Gaps interrupt micro-Doppler history accumulation, so larger factors may prevent a sufficiently long continuous window from forming. Use 1 for continuous micro-Doppler analysis. Communication traffic and RF transmission timing are unaffected. Update the backend and viewer together to the same version.
